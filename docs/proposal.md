# Moon TraceLens 项目申报书

GitHub：待创建公开仓库，拟用 `btlqql/moon-tracelens`。
当前阶段：选题与架构规划；本文按立项阶段表述功能、交付和验收目标。

## 项目简介与通用价值

把异构日志转为可查询事件，建立请求和作业的关联时间线。项目采用 MoonBit 实现核心处理能力，提供可复用库接口与命令行入口，使使用者能够把同一能力嵌入应用、离线处理或 CI 流程。适用范围通过不同用途的完整示例说明，并以输入、判断过程和可核验输出体现实际价值。

## 核心功能

JSONL/文本格式解析；时间与时区归一化；多行错误事件；结构化字段索引；查询与分组聚合；按明确 ID 的事件关联；增量读取与检查点；报告和 CLI。关联报告显示缺失事件与时钟不确定性，不把先后顺序冒称因果证明。

## 三个完整使用场景

1. 服务故障排查：输入同一请求在网关和应用中产生的日志，按 request ID 关联并统一时间；输出请求时间线、错误位置与缺失事件，使开发者能够复核超时发生在哪一步。

2. 批处理失败复盘：输入多作业的启动、失败、重试和完成事件，重建作业尝试记录；输出最终失败作业、重试次数及失败前后上下文，供运维选择重新执行范围。

3. 发布前后异常对比：输入带版本标识的两组日志，按相同时间窗口和过滤条件统计错误比例与耗时；输出对比结果与原始事件引用，支持回归调查而非自动断言发布导致故障。

## 技术路线与工程实现

将解析器输出归一化为带时间、严重度、来源和关联 ID 的事件；查询执行与增量文件适配分层，检查点显式记录读取位置和文件标识。核心逻辑采用有类型的数据结构、明确错误结果和可测试执行步骤；文件、网络或进程适配与核心处理分层。实现过程中用小规模确定性输入建立正确性基准，再使用真实场景和规模数据检查可用性。对外暴露稳定接口，避免把演示脚本作为唯一使用方式。

## 预计交付与验收方式

交付目标包括公开 MoonBit 源码、库接口、CLI、三个完整场景及输入来源、单元与集成测试、适用目标的 CI、安装使用说明、设计与边界文档、源码统计及独立安装验证记录。有效生产 MoonBit 源码内部估算为 4,000–7,000 行，测试、示例、生成语料和辅助脚本分别统计，该估算不作为官方验收门槛。

十万事件的查询与聚合和独立参考结果一致；增量读取与一次性读取的结果一致。失败验证覆盖非法时间、日志截断/轮转、损坏检查点、缺关联 ID 与多行栈。十月做离线日志分析，不包含分布式采集平台或在线告警服务。

拟原创实现本项目的数据模型、处理流程和业务判断，不把九月项目旧代码或简单拆分计入此次新成果。[RFC 5424：日志事件参考](https://www.rfc-editor.org/info/rfc5424/)作为设计或标准参考，当前没有声明已复制该项目代码。计划采用 Apache-2.0；实际采用的依赖、参考实现和数据集逐项记录版本、链接、许可证与使用范围。生态查重仍须补齐同类项目的接口、能力和差异证据，不能声称已证明唯一性。
